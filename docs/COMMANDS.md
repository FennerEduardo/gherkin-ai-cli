# Command reference

`gherkin-ai` and `ghk` are the same binary. Run `ghk <command> --help` for the authoritative list of options.

**Global options:**

- `--project <dir>`: target project, skipping workspace detection;
- `--yes` / `--non-interactive`: never prompt;
- `--spec-dir <dir>`: where the `.feature` files are;
- `--json`: exactly one JSON document on stdout;
- `--verbose` / `--quiet`: logging level;
- `--dry-run` and `--stdout`: for commands that write files.

Exit codes are listed in [ENTERPRISE.md §5](ENTERPRISE.md#5-automation-contract-exit-codes-and---json).

## Specification

| Command | Purpose | Main options |
|---|---|---|
| `create` (`c`, `new`) | Write a feature interactively, or headless from a JSON file | `-o <file>`, `--headless --config <file>`, `-C` (single prompt) |
| `speckit import` | Convert GitHub Spec Kit `specs/NNN-*/spec.md` into `.feature` files | `--dir <specs>`, `--out <features>`, `--force` |
| `speckit export` | Write `.feature` files as Spec Kit specs | `--out <specs>`, `--force` |
| `lint` | Specification quality rules and score | `-f <file>`, `--threshold <0-100>` (exit 4 below), `--rules`, `--all` (every project in the repo) |
| `validate` (`v`) | Specification and architecture rules; optional OpenAPI / AsyncAPI comparison | `-f`, `--openapi <file>`, `--asyncapi <file>`, `-t <dir>` |
| `export` (`e`) | Agent context bundle for one feature | `-f`, `--format md\|json`, `-o` |
| `lang` | CLI interaction language (`en`, `es`). Generated prompts stay in English. | `-s <locale>` |

## Generation

| Command | Purpose | Main options |
|---|---|---|
| `init` (`i`) | Create `gherkin-ai.config.json` for a stack | `-l`, `-f`, `-o`, `-d`, `-m`, `--frameworkVersion`, `--ormVersion`, `--frontendFramework`, `--enterprise` |
| `stacks` | Supported stacks and their tier | `--json` |
| `generate` (`g`) | Contracts, domain kernel, tests, runtime, application layer and prompts for a feature. Never overwrites edited or protected files (writes `<file>.ghk-new`). `--review` shows each `.ghk-new` diff and takes the generated version or keeps yours (a kept version is not offered again; non-interactive: exit 4 while versions are pending) | `-f <file>`, `-c <config>`, `--force`, `--dry-run`, `--review`, `--accept-new`, `--keep-mine` |
| `add` (`a`) | Inject contracts and prompts into an existing module (brownfield) | `-f`, `-t <dir>` |
| `detect` (`d`) | Detect the stack of an existing project | – |
| `upgrade` | Assisted upgrade of a project generated by an older version, on a new branch | `--apply`, `--check` (exit 4), `--commit`, `--branch`, `--no-git`, `--no-regenerate`, `--prune`, `--cli`, `--force`, `--kernel` (refresh only the runtime kernel), `--all`, `--dry-run` |

`ghk upgrade` never changes the current branch and never pushes. See [MIGRATION-3.0.md](MIGRATION-3.0.md#assisted-upgrade-ghk-upgrade) and [MIGRATION-3.1.md](MIGRATION-3.1.md).

## Verification and governance

| Command | Purpose | Main options |
|---|---|---|
| `converge` (`conv`) | Spec-to-code convergence across seven dimensions (coverage is `n/a` without a report) | `-f`, `--threshold` (exit 7 below), `--all` |
| `diff` | Drift between a feature and a DTO or contract | `-f`, `-t <file>` |
| `impact` | Files affected by a change to a feature | `-f` |
| `risk` | Delivery risk of a change: LOW / MEDIUM / HIGH / CRITICAL, with evidence. Weights from `policy.risk.weights`; `--calibrate` proposes them from the git history | `--base <ref>`, `--files <list>`, `--fail-on <level>` (exit 4), `--calibrate`, `--commits <n>`, `--write` |
| `report` | Publishes lint, convergence and delivery risk on the pull / merge request. GitHub: annotations on the .feature lines and a job summary. GitLab: a Code Quality report. No token needed | `--provider github\|gitlab`, `--base <ref>`, `--threshold <score>`, `--fail-on <level>` (exit 4), `--out <file>` |
| `graph` | Traceability graph: feature → scenario → command / event / endpoint → files and tests (also `@trace:<Symbol>` tags, `ghk:implements <Symbol>` comments, where the aggregate name links to its feature, and `ghk:trace feature=<path>` comments) | `--trace <symbol>`, `--scope <feature>`, `--format summary\|json\|mermaid\|dot`, `-o` |
| `firewall check` | Would the firewall allow an agent action? | `--write <path>`, `--exec <cmd>`, `--network <host>`, `--secret <name>`, `--tool <name>`, `-f <feature>` (exit 5 unless ALLOW) |
| `firewall policy` | Effective firewall rules, including a feature's scope | `-f <feature>` |
| `firewall hook` | Claude Code `PreToolUse` hook (reads the tool call on stdin) | `-f <feature>` |
| `verify` (`v-loop`) | Run the tests; optionally let an LLM propose fixes. With `--auto-fix`, mechanical failures (missing dependency, out-of-sync lockfile) are fixed with the toolchain's dependency command first, and failures that are not code bugs (no database or broker, pending `.ghk-new` versions) stop with an explanation instead of a model call | `-c <cmd>`, `--docker`, `--docker-network`, `--isolated`, `--auto-fix`, `--apply`, `--max-retries`, `--allow-unattended-writes`, `--force-branch`, `--services` (PostgreSQL + RabbitMQ integration suite) |
| `quality` (`q`) | Coverage and delivery risk summary | – |
| `evaluate` (`eval`) | File and class size, and pattern compliance | `--max-file-lines`, `--max-class-lines` |
| `pr-review` | Check a diff against a feature | `-f`, `--diff <file>` |
| `bench init` / `bench run` | A/B benchmark of your agent with and without gherkin-ai | `--agent <cmd>`, `--repetitions`, `--arms`, `--out`, `--dry-run` |

`verify --docker` runs the tests in the stack's toolchain image:

- no network (`--docker-network bridge` when dependencies must be downloaded);
- 2 GB of memory, 2 CPUs and 512 processes;
- all capabilities dropped and a read-only root filesystem.

Override the limits in `sandbox.*`.

## Agents

| Command | Purpose | Main options |
|---|---|---|
| `implement` (`impl`) | Implementation prompt and context package for a feature | `-f`, `--docker`, `-C` (compact), `--no-audit`, `--inventory` |
| `context` | Write project conventions and security notes into `.ghe/` | – |
| `mcp` | Start the MCP server (stdio, read-only by default) | – |
| `mcp install` | Register the server, version-pinned, in MCP clients | – |
| `skill` (`s`) | IDE rules files (`.cursorrules` and others) | – |
| `autopilot` (`auto`) | Experimental: requirement → spec → code → verify loop | `-r <file>`, `--apply`, `--allow-unattended-writes`, `--force-branch`, `--services` (PostgreSQL + RabbitMQ integration suite) |
| `agent-log` | Record or list actions taken by an agent | `-a <text>`, `-f`, `-l`, `--clear` |
| `web` (`w`, `ui`) | Local Web Studio (token-protected, localhost only) | `-p <port>` |
| `doc` (`site`) | Static documentation site from the features | – |

`verify --auto-fix --apply` and `autopilot --apply` write files only after these guards pass:

- the CI guard and the protected-branch guard;
- the agent firewall: files it does not allow become `.ghe/patches/*.proposed`.

## Configuration, credentials and audit

| Command | Purpose | Main options |
|---|---|---|
| `config show` | Effective configuration | `--sources` (which layer set each value), `--json` |
| `config validate` / `config schema` | Validate the configuration layers, or print the JSON Schema | `-c <file>` |
| `login` | Store a provider API key in the OS keychain | `--provider <name>`, `--api-key-stdin` |
| `logout` | Remove stored keys | `--provider <name>` |
| `auth status` | Provider, model, credential source, endpoint, proxy (never the secret) | `--json` |
| `audit` (`inventory`) | Feature inventory and history | `-f`, `--json`, `--html`, `--clear` |
| `audit export` | Security audit trail for a SIEM | `--format jsonl\|csv`, `--since 7d`, `-o` |
| `sbom` | CycloneDX SBOM of the project | – |
